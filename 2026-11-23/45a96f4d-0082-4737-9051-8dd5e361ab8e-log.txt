## 评审结论

本次变更存在日志推送失败却报告成功、重复运行失败及评审内容可能泄露的风险，建议修复后再合并。

### 1. [P1] 推送被拒绝时仍返回成功链接

**位置：** `OpenAiCodeReview.writeLog()`，`git.push().call()` 之后

JGit 的 `push().call()` 返回推送结果；服务端拒绝更新时，不一定抛出异常。当前代码没有检查 `RemoteRefUpdate` 的状态，仍会返回日志 URL。

例如两个任务同时克隆并提交时，后推送的任务可能因非 fast-forward 被拒绝，但调用方会收到一个实际不存在的链接。

**建议：**检查每个 `PushResult` 中的更新状态，对拒绝状态明确报错；并发场景下可重新拉取、重建提交并有限重试。

### 2. [P1] 评审结果被写入硬编码仓库，可能泄露代码信息

**位置：** `OpenAiCodeReview.writeLog()`，仓库 URI

所有使用该 SDK 的项目都会将 LLM 评审结果推送到固定仓库 `zdkk619/openai-code-review-log`。评审结果可能包含原始代码片段、漏洞和业务信息；如果目标仓库公开或访问范围过大，就可能造成泄露。同时，调用方也无法选择符合自身权限要求的日志仓库。

**建议：**将目标仓库配置化，明确校验目标地址，并使用仅对该仓库有必要写权限的凭据。部署时确认仓库可见性及日志保留策略。

### 3. [P2] 固定克隆目录导致重复执行失败

**位置：** `OpenAiCodeReview.writeLog()`，`.setDirectory(new File("repo"))`

成功执行后 `repo` 目录不会被删除；在同一工作目录再次运行时，克隆通常会因目标目录非空而失败。并发运行也会争用同一目录。

**建议：**每次执行使用独立的临时目录，并在 `finally` 中关闭 `Git`、清理目录；覆盖重复执行和并发执行测试。

### 4. [P2] 返回链接假定默认分支为 `main`

**位置：** `OpenAiCodeReview.writeLog()`，返回 URL

克隆和推送使用仓库的默认分支，但返回链接固定为 `blob/main/`。若目标仓库默认分支不是 `main`，即使推送成功，返回的链接仍然无效。

**建议：**根据实际推送的分支构造链接，或将分支作为配置，并确保克隆、提交、推送和 URL 使用同一分支。

### 5. [P2] 日志文件编码不固定

**位置：** `OpenAiCodeReview.writeLog()`，`new FileWriter(logFile)`

`FileWriter` 使用运行环境的默认字符集。在 Java 17 的不同系统中，中文评审内容可能以非 UTF-8 编码写入，导致仓库页面或其他环境读取时乱码。

**建议：**显式使用 UTF-8，例如 `Files.newBufferedWriter(path, StandardCharsets.UTF_8)`。

### 其他建议

- `llmCodeReview` 从 `public` 改为 `private` 会破坏已有 SDK 调用方的源码兼容性；若属于对外 API，应保留或按版本策略弃用。
- 不建议提交 `data/log/*.log` 运行产物；其中包含本地路径和历史启动错误。建议移除并加入 `.gitignore`。
- 建议增加推送拒绝、重复运行、并发运行、非 `main` 分支和中文日志编码的测试。
