## 评审结论

**建议暂缓合并。** 当前变更存在凭据泄露、通知对象硬编码以及返回值语义变化等问题。

### 1. [严重] 微信凭据被提交，访问令牌被输出到日志

**位置：** `WXAccessTokenUtils.java`：`APPID`、`SECRET` 常量及响应日志

公众号密钥直接写入源码，获取令牌后又打印完整响应，其中包含 `access_token`。源码或日志一旦被其他人访问，可能导致公众号接口被滥用。

**建议：**
- 立即在微信后台重置已泄露的密钥，并按团队规范处理仓库历史和相关日志。
- 通过环境变量或密钥管理服务注入凭据，禁止打印密钥和令牌。

### 2. [高] 评审方法的返回值发生不兼容变化

**位置：** `OpenAiCodeReview.java`：`return sendMessageNotification(logUrl)`

原来返回评审日志 URL，现在返回微信接口响应或错误字符串。依赖原返回值的调用方可能无法获取日志链接；即使日志已成功写入，通知失败时也可能被误认为整个评审失败，重试还可能产生重复日志。

**建议：** 保持原有返回值契约，或明确引入包含 `logUrl`、通知状态和错误信息的结果对象，并同步修改调用方。通知失败不应丢失已生成的日志 URL。

### 3. [高] 通知接收人和内容被硬编码

**位置：** `Message.java`：`touser`、`template_id` 默认值；`OpenAiCodeReview.java`：`project`、`review`

所有评审都会发送给固定用户，并显示测试项目和固定评审内容。这既会产生错误通知，也可能将实际评审日志链接发送给非预期接收人。

**建议：** 将接收人、模板 ID 配置化，并从实际项目和提交信息构造模板数据；缺少必要配置时明确报错或跳过通知，不使用真实用户作为默认值。

### 4. [高] 未正确处理微信接口失败

**位置：** `WXAccessTokenUtils.getAccessToken()`、`OpenAiCodeReview.sendPostRequest()`

- 获取令牌失败时返回 `null`，后续仍会使用该值请求发送接口。
- 发送接口只读取响应文本，未检查微信响应中的 `errcode`；HTTP 200 也可能表示业务失败。
- 异常被转换成普通字符串返回，调用方难以可靠区分成功和失败。

**建议：** 校验令牌及微信业务响应，读取并处理 HTTP 错误响应；通过异常或结构化结果向调用方报告失败，避免将错误当作成功结果。

### 5. [高] 外部请求没有超时

**位置：** 两处 `HttpURLConnection` 创建代码

获取令牌和发送消息均未设置连接、读取超时。微信接口或网络异常时，评审流程可能长时间阻塞。

**建议：** 为两类请求设置合理的连接和读取超时，并确保连接及响应流关闭。

### 6. [中] 测试会调用真实微信接口，且没有断言

**位置：** `TestWX.test_wx()`

测试使用真实凭据和默认接收人发送消息；同时捕获并打印异常，没有断言，因此即使发送失败也可能显示测试通过。

**建议：** 使用可注入的 HTTP 客户端和模拟响应，覆盖成功、微信业务错误、超时及令牌获取失败等场景。真实接口测试应单独隔离并显式启用。

### 7. [待确认] 新依赖未指定版本

**位置：** `openai-code-review-sdk/pom.xml`：`fastjson2` 依赖

若父 POM 或导入的 BOM 未管理 `fastjson2` 版本，Maven 构建会失败。当前 diff 未展示父级配置，建议确认版本由依赖管理统一提供。
